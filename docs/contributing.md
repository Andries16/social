# Contributing

Keep changes focused by feature. Prefer small React components and explicit API boundaries. Do not introduce frameworks outside the agreed stack.

Before opening a pull request:
1. npm install
2. npm run build
3. npm test
4. npm run build-storybook
5. npm run e2e

Use semantic commit messages such as feat:, fix:, test:, docs: and refactor:. Never commit credentials, generated databases or user media.
